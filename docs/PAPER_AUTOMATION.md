# 자동 paper 매수·매도 · 2026-11-25

사용자가 기존 일회성 실행을 자동 매매로 확장하도록 요청했다. 같은 Alpaca paper 계정·Momentum 규칙·기존 주문 원장을 이어 쓴다. 이후 사용자가 제시한 모의 현금에 따라 전략 예산을 $5,000에서 **$100,000**, 종목별 슬롯 한도를 $1,000에서 **$20,000**으로 변경했다. 실거래 주소/설정과 차입은 계속 차단한다.

## 현재 운영 상태

macOS 사용자 LaunchAgent `com.quantcore.paper-trading`을 등록했다.5분마다 실행하고 로그인 시 시작하는 구성이다. 최초 실제 자동 주기는11:36 KST에 정상 완료됐고, 기존 AAPL2주·TSLA2주 외의 신규 주문/POST는0건이었다. 처음에는 Python의 Desktop 폴더 접근 허용을 기다렸지만, 이후11:43 KST의 launchd 직접 실행(parent PID1)과 정상 종료 코드0을 확인했다.

11:55 KST의 예산 변경에서 기존2주씩은 취소됐고 **AAPL53주·TSLA48주**가 새로 접수됐다. 두 주문의 filled_qty는0, 최대 매수 지정가 대금은 $37,625.75다. 나머지 세 종목에는 현재 매수 신호가 없어 현금을 유지한다. 다음 정규장은2026-11-25 23:30 KST다. 주문은 브로커에 남아 지정가 조건에 따라 처리되며, 주문 접수와 체결은 구분한다. 하루 이상의 실제 자동 운용 성과나 수익률은 아직 측정하지 않았다.

## 자동 주기

1. 미체결 주문을 broker와 대사하고 계정 시계·보유 수량·평가액을 기록한다. 이미 종료된 주문은 저장된 최종 filled_qty를 사용해 전체 주문 이력을 매번 API로 조회하지 않는다.
2. 매 주기 실제 계좌 NAV와 독립 리스크 한도를 검사하며, 위반한 자체 대기 매수만 취소하고 새 매수를 제한한다. 정규장 중에는 상태를 관찰한다. 미실행 세션이고 개장5분 이내면 이전 완료 세션의 신호로 실행을 보완할 수 있지만, 그 이후에는 당일 매매를 따라잡지 않는다.
3. 정규장 마감10분 뒤부터 최신 완료 일봉을 확보하고 다음 거래일 목표 수량을 계산한다. 다음 거래일이 휴일 뒤라면 XNYS 달력과 broker의 next_open을 사용한다. 조기 폐장과 DST를 반영한다.
4. Momentum 활성 종목을 매수·재조정하고 비활성 종목의 원장 소유 수량을 매도한다. 미체결 매도 대금을 미리 쓰지 않으며, 매수가 예산/현금에 걸려도 매도를 막지 않는다. 부족한 매수는 수량을 줄이거나 다음 일별 평가까지 미룬다.
5. 세션별 완료 상태와 기존 client_order_id를 저장하므로5분마다 같은 주문을 추가하지 않는다. 새로운 가격으로 같은 날 취소/재주문을 반복하지 않는다. 이미 알려진 split이나 원장 불일치가 있으면 중단한다.

자동 감시는5분 주기지만 **전략 판단은 일봉 기반**이다.5분 초단타나 매일 반드시 거래하는 전략이 아니다. 지정가1% 제한과 DAY/정규장 정책, 종목당 $20,000 매수 상한을 유지한다.

## 데이터와 상태 파일

- `datasets/paper_equities/`: 최근100개 완료 세션을 보관하는 별도 캐시. 검증된 기존 자료를 재사용하고 새로 필요한 세션만 공식 IEX1분봉으로 수집한다. 최근 기간 기업행사도 조회한다. split 기준은 창 전체에서 다시 계산해 오래된 배수와 신규 배수를 잘못 이어 붙이지 않는다.
- `datasets/real_equities/`: 기존 백테스트의 동결본/포인터는 수정하지 않는다.
- 입력·공개 시각·해시를 검사하고, 부분 수집 실패는 정상 latest 포인터를 덮어쓰지 않는다. 첫 실제 갱신은 이미 최신인 기존 시세100세션·500행을 재사용하고 기업행사를 갱신했으며, 추가 분봉 다운로드는0행이었다. 다음 신규 거래일의 실제 증분 수집은 아직 미래이며, 해당 경로는 MockTransport 데이터로 검사했다.
- `artifacts/paper_trading/automation/state.json`: 최근 완료 시각·단계·평가한 세션·주문 상태·오류·다음 작업. `launchd.stdout.log`/`launchd.stderr.log`는 실행 로그다. API 키 값은 plist/원장/로그에 넣지 않는다.
- `paper_account_equity_change`는 최초 관찰한 paper 계정 전체 평가액과의 차이다. 입출금/계정 초기화 조정이나 전략 전용 성과 귀속을 하지 않으므로 별도의 전략 수익률로 해석하지 않는다.

## 예산 변경

활성 예산은 `journal.sqlite3`의 계정/전략 설정에서 읽는다. 새 원장의 초기값은 $5,000이고 이번 계정은 사용자가 승인한 $100,000으로 변경했다. 기존 CLI의 `--budget`만 바꾸면 계정 원장 검사가 중단하며, 아래 전용 경로로 변경한다.

```bash
.venv/bin/python scripts/set_paper_budget.py --budget 100000 --resume --execute --env-file /authorized/path/.env
```

자동 신규 주문을 잠시 막고 원장을 백업한다. 이 프로그램의 미체결 주문만 취소하고 최종 상태를 확인한 뒤 부분 체결 수량까지 다시 대사한다. 기존 이력은 삭제하지 않으며 예산 revision을 증가시켜 새 목표의 고유 ID를 만든다. 같은 예산의 반복 실행은 revision을 늘리거나 다시 취소하지 않는다. 자동 작업의 세션 완료 키도 revision을 포함하므로 이전 예산으로 완료한 세션과 혼동하지 않는다.

취소가 확정되지 않으면 예산은 그대로이고 자동 작업은 일시 중지된다. 새 주문 제출 중 문제가 발생하면 변경된 예산/이력을 보존하고 신규 주문을 막는다. 가용 현금으로 수량을 제한하며 더 큰 margin buying power를 자금으로 쓰지 않는다. `--resume` 없이 변경하면 자동 작업은 멈춘 상태를 유지하고, `--execute`는 명시적인 재개가 있어야 사용할 수 있다.

## 상태 확인과 중지

프로젝트 루트에서 실행한다. 서비스가 인증 파일 경로를 기억하므로 매 주기 새 터미널이나 노트북을 열 필요가 없다.

```bash
# heartbeat와 macOS 서비스 상태
.venv/bin/python scripts/manage_paper_automation.py status
# 새 주문 중지. 이미 접수된 주문은 Alpaca에 남는다.
.venv/bin/python scripts/manage_paper_automation.py pause
# broker/원장 문제를 확인한 후 재개
.venv/bin/python scripts/manage_paper_automation.py resume
# 자동 작업 등록 해제 및 새 주문 중지
.venv/bin/python scripts/manage_paper_automation.py uninstall
```

이미 접수된 주문까지 취소하려면 별도로 `scripts/run_paper_trading.py cancel --env-file /authorized/path/.env`를 실행한다. 이 명령도 프로그램 원장 소유의 미체결 주문만 취소한다.

다른 Mac에서 등록하려면:

```bash
make real-setup
.venv/bin/python scripts/manage_paper_automation.py install --env-file /authorized/path/.env
```

설치 파일은 `~/Library/LaunchAgents/com.quantcore.paper-trading.plist`다. 삭제/재개는 위 명령을 사용하며 원장을 지워 중복 방지를 해제하지 않는다. Mac이 켜져 있고 사용자 로그인·네트워크 연결·폴더 접근 허용이 필요하다. 잠자기 중에는 작업이 실행되지 않으며 깨어난 뒤 현재 시점의 다음 주기를 처리한다. 놓친 과거 주문을 소급 체결하지 않는다. 이미 접수한 주문은 Mac의 실행 상태와 별개로 Alpaca가 처리한다.

## 장애 처리와 검증

일시적인 GET/수집 장애는 최초 실패 뒤5/15/45분 간격으로 재시도하며, 연속4번째 실패 시 신규 주문을 차단한다. 주문 접수 여부가 불명확하거나 원장/계정/자료가 맞지 않으면 즉시 `blocked`를 기록한다. 자동 재개하지 않는다. `resume`으로 상태를 풀어도 미해결 POST 원장은 그대로 대사하므로 중복 주문을 허용하지 않는다. 외부 메시지 전송은 추가하지 않았으며 로컬 heartbeat/로그로 상태를 확인한다.

전체133개 테스트 통과,25.13초, 문장 커버리지96.25%(`quantcore`+`apps/api`), 기존 TestClient 경고1개. paper 관련51개 중 이번 추가는18개로, 다음 세션 자동 매도·휴일/DST/조기 폐장·pause/resume·불명확 주문 차단·일시 장애 제한·매수 자금 부족 시 매도 유지·LaunchAgent 구성·증분 병합/미래 split 배제/실패 포인터 보존을 확인했다. Ruff/플리스트 구문 검사가 통과했다. 웹 소스와 백테스트 엔진은 수정하지 않아 기존 UI 빌드/브라우저/노트북 전체 실행을 다시 반복하지 않았다.

예산 변경 후에는 전체139개 테스트 통과,29.66초, 커버리지96.21%다. 추가6개 사례는 이력/원장 백업·예산 revision과 반복 실행·취소 중 부분 체결·취소 미확정·재제출 실패 시 중지·현금 이상의 buying power 배제·타인 주문/한도 초과 차단을 확인했다. 실제 변경 및 최종 자동 작업 상태는 [paper_budget_validation.json](paper_budget_validation.json)에 기록한다.

## Paper 실적 누적 추가 — 2026-11-25

매 tick의 주문·리스크 처리가 끝나면 읽기 전용 실적 수집을 실행한다. 평가액5분 관측,90일 일별 계좌 이력, 체결/비거래 활동을 원장에 누적하고 대시보드의 **모의투자 현황**으로 제공한다. STOP 중에도 조회가 가능하면 실적 수집은 계속한다. 실적 조회 오류는 별도로 기록하며 새 리스크 검사를 건너뛰거나 기존 정지를 해제하지 않는다. [정의·실행](PAPER_PERFORMANCE.md).

## 기업 분류·기업행사 대사 추가 — 2026-11-25

주기 시작 시 버전/해시가 확인된 SEC SIC·Alpaca 자산/기업행사 자료를 확인한다(참조자료 갱신은24시간 주기). 자체 FILL과 분할/배당/종목변경 원장을 브로커 보유량에 대사한 뒤 기존 소유권·리스크 검사를 실행한다. 분할/종목변경 영향을 받는 자체 대기 주문만 취소하고 최종 확인 전에는 진행하지 않는다. 미확인 종목 이관·단주/복잡한 행사·원장 불일치는 review_required로 거래를 중단한다. 원래 주문 이력과 예산을 보존한다. 현재 분류는 수집 시각 이후부터 적용하며 과거 평가에는 소급하지 않는다. 기간 분리 연구는 paper의 Momentum60을 자동 변경하지 않는다.
